# 03. 메타코드 AI LLM 부트캠프 학습 순서

> 부트캠프 6기(2026.04 ~ 09) 모듈을 이 프로젝트 순서에 맞춰 재배열한 계획.
> 원칙: **프로젝트에 지금 당장 필요한 모듈부터** 듣고, 기초 모듈은 건너뛰거나 필요할 때만 돌아간다.
> 왜: 24주 커리큘럼을 순서대로 따라가면 로드맵 10주 안에 RAG·메모리·MCP까지 도달하지 못한다.

## 핵심 트랙: 9 → 10 → 11 → 12 → 13주차

이 다섯 모듈이 프로젝트의 뼈대다. 순서를 바꾸지 않는다.

### 9주차 NLP
- 목표: 토큰·임베딩·어텐션이 무엇인지 코드로 만져본다.
- 프로젝트 적용: 한국어 임베딩 모델 후보(예: `BAAI/bge-m3`, `intfloat/multilingual-e5`) 중 1개 선정 근거를 노트북에 기록.
- 체크: `notebooks/`에 임베딩 유사도 실험 1개.

### 10주차 LLM·프롬프트
- 목표: 시스템 프롬프트·few-shot·구조화 출력(JSON) 다루기.
- 프로젝트 적용: `persona/artist_card.yaml` → 시스템 프롬프트 변환 함수, 세션 요약 프롬프트 초안.
- 체크: 페르소나 규칙 위반 0/1 judge 프롬프트 1개.

### 11주차 RAG
- 목표: 청킹 → 임베딩 → 벡터DB → 검색 → 프롬프트 주입 파이프라인.
- 프로젝트 적용: `src/retrieval/` + `src/memory/episodic.py`.
- 체크: 2세션 연속 대화에서 앞 세션 회상 확인.

### 12주차 Agent·LangGraph
- 목표: 상태 그래프, 조건 분기, 툴 호출.
- 프로젝트 적용: `src/agent/` 대화 그래프, 쓰기 정책 분기(규칙 / LLM).
- 체크: 그래프 다이어그램 1장을 README에 추가.

### 13주차 MCP
- 목표: 툴 서버 정의·클라이언트 연결.
- 프로젝트 적용: 메모리 read/write를 MCP 툴로 노출. 부트캠프 실습 코드를 그대로 재활용.
- 체크: 외부 클라이언트에서 사실 메모리 조회 성공.

## 보강 트랙: 6~7주차 PyTorch 문법

- 언제: 핵심 트랙과 병행. 하루 30분 단위로 짧게.
- 왜: 로컬 7~8B 모델 로딩·배치 임베딩·GPU 메모리 관리는 텐서 조작 감각이 없으면 디버깅이 안 된다.
- 범위: 텐서 연산, `DataLoader`, `no_grad`, 디바이스 이동, `float16`/`bfloat16`. 모델 학습 루프는 보류.

## 평가 트랙: 15~16주차 캐글 평가 방법론

- 언제: 로드맵 6~7주차(평가셋 합성·judge 구현 시점).
- 왜: 평가 지표 설계, 데이터 분할, 결과 재현성은 이 프로젝트의 핵심 기여(한국어 벤치마크)와 직결된다.
- 적용: F1·Spearman 계산 코드, 결과표 포맷, 시드 고정 관행.

## 후반 트랙: 17주차 CI/CD

- 언제: 로드맵 8주차 이후. 코드가 안정된 다음에 붙인다.
- 왜: 초반에 CI를 붙이면 매 커밋마다 깨진 테스트를 고치느라 진도가 막힌다.
- 적용: GitHub Actions에서 `pytest` + `eval/run_eval.py --smoke` 실행.

## 건너뛰는 모듈: 1~3, 5, 8주차

- 1~3주차(Python·수학·ML 기초), 5주차(통계), 8주차(DL 기초)는 기계공학·수학 편입 배경과 부트캠프 이전 경험으로 대체한다.
- 단, 8주차 DL 기초 중 "역전파·옵티마이저" 파트는 PEFT를 시작할 때 다시 본다.

## 보류: 14주차 PEFT, 18주차 이후 MLOps

- 로드맵 10주 안에는 다루지 않는다. API 모델로 실험을 먼저 끝내는 것이 우선.
- 12월 이후 확장 과제: 로컬 Qwen3/EXAONE에 페르소나 말투 LoRA 파인튜닝 → 비교군 추가.
